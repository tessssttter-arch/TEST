# Технический аудит и карта архитектуры: «КАТАЛОГ_КУРАТОР (V4.0)»

## 1. Синопсис проекта и назначение
**Curator Catalog Dashboard (V4.0)** — изолированное SPA-приложение, предназначенное для администрирования, модерации, тонкой кураторской очистки и наценки товарной номенклатуры перед экспортом на витрины или в сторонние каналы. Приложение работает в браузере клиента без прямого выделенного бэкенда для хранения товаров, полагаясь на локальное транзакционное хранилище **IndexedDB** высокой емкости.

---

## 2. Архитектура стейта (State Management)
Проект использует двухслойный паттерн управления состоянием через **React Context**, полностью исключающий Prop-Drilling:
1.  **CatalogDataContext**: отвечает за физические операции с данными (массив товаров, асинхронный импорт, массовое удаление, групповое изменение тегов и наценок).
2.  **CatalogUIContext**: управляет визуальным слоем приложения (поисковые запросы, фильтры по категориям/тегам, пагинация, системные оповещения Toast и глобальные модальные диалоги подтверждения Confirm).

Все модификации стейта используют оптимистичный интерфейс (Optimistic UI) — изменения отображаются мгновенно, а физическая запись в IndexedDB буферизуется и происходит в фоновом режиме.

## 3. Исчерпывающее описание файловой структуры и функций компонентов

Ниже представлена полная интерактивная карта всех файлов в директории `src/` с детальным описанием их технического назначения, связей и зон ответственности.

### 3.1. Точки входа и конфигурация
*   **`src/main.tsx`**
    *   *Назначение*: Точка монтирования React-приложения. Оборачивает компонент `<App />` в `<StrictMode>`.
    *   *Связность*: Низкая. Служит исключительно стартовым триггером.
*   **`src/App.tsx`**
    *   *Назначение*: Главный композиционный слой. Оборачивает интерфейс `CatalogDashboard` в `ToastProvider` и `CatalogProvider`. Реализует экранный flow: скелетоны загрузки (`isLoading`), обработку пустых состояний базы и отфильтрованных списков.
    *   *Связность*: Высокая. Оркестрирует все глобальные компоненты (модальные окна, лайтбоксы, панели).
*   **`src/types.ts`**
    *   *Назначение*: Декларация типов доменной модели `Product`, режимов импорта/экспорта и структуры отчетов сравнения `DiffReport`. Содержит детерминированную функцию `getTagColor(tag)` для генерации стилей тегов на основе хэш-кода строки.
    *   *Связность*: Очень высокая. Импортируется практически в каждом файле проекта.

### 3.2. Доменный слой и сервисы (`src/services/`)
*   **`src/services/catalog-db.ts`**
    *   *Назначение*: Транзакционный шлюз доступа к IndexedDB (`appDataDB`, версия 1). Реализует оптимизированную пакетную очередь записи (**Batch Queue**) с задержкой в 300мс для предотвращения избыточных дисковых транзакций при частых изменениях.
    *   *Связность*: Очень высокая. Напрямую связывает контекст данных и постоянную память устройства.
*   **`src/services/catalog-init.ts`**
    *   *Назначение*: Сервис первичного старта приложения. Проверяет флаг миграции, при необходимости переносит данные из устаревшего `localStorage` (версия V3), а при пустой IndexedDB осуществляет принудительный засев (seed) демонстрационного профессионального промо-каталога.
    *   *Связность*: Высокая. Зависит от API БД и статических демо-данных.
*   **`src/services/product-normalizer.ts`**
    *   *Назначение*: Валидация и жесткая нормализация полей входящих структур товаров к строгому контракту `Product`. Заполняет дефолтные значения (UUID вместо пустых ID, приводит цены к числам, формирует массив оригинальных размеров).
    *   *Связность*: Высокая. Используется при любом виде импорта и записи.

### 3.3. Пользовательские утилиты и хуки (`src/hooks/`)
*   **`src/hooks/useUrlFilters.ts`**
    *   *Назначение*: Двунаправленная синхронизация состояния фильтров, поиска и параметров пагинации с URL-адресом (URL Search Params). Обеспечивает "F5 safe" поведение — сохранение контекста просмотра при перезагрузке страницы.
    *   *Связность*: Средняя. Связан с `CatalogContext`.
*   **`src/hooks/useKeyboardShortcuts.ts`**
    *   *Назначение*: Перехватчик нажатия горячих клавиш клавиатуры для ускоренной модерации (навигация по страницам, быстрое переключение режимов сетки, выделение элементов).
    *   *Связность*: Низкая.
*   **`src/hooks/useLongPress.ts`**
    *   *Назначение*: Вспомогательный хук для обработки долгого нажатия мыши или тача (используется для специфичных групповых выделений).

### 3.4. Вспомогательные утилиты (`src/utils/`)
*   **`src/utils/tag-normalizer.ts`**
    *   *Назначение*: Очистка, фильтрация дубликатов, приведение к нижнему регистру и обрезка пробелов в массивах тегов.
*   **`src/utils/textReplace.ts`**
    *   *Назначение*: Утилиты автоматического текстового поиска и замены в описаниях с поддержкой регулярных выражений (Regex). Включает предустановленные паттерны (удаление ссылок на VK/Telegram, HTML-тэгов, скрытие телефонов).

### 3.5. Компоненты интерфейса (`src/components/`)
*   **`CatalogFilters.tsx`**: Панель фильтров (поиск, категории, теги, переключатели «только избранное/модифицированное/выбранное»).
*   **`BulkActionsPanel.tsx`**: Центр групповых операций. Позволяет массово изменять цены (проценты или фиксированные суммы), очищать/добавлять теги, сбрасывать кураторские правки или безвозвратно удалять пачки выбранных товаров.
*   **`BulkTagManager.tsx`**: Тонкий инструмент группового добавления/удаления или замены тегов для выделенных позиций.
*   **`ParserImportPanel.tsx`**: Интерфейс импорта. Поддерживает парсинг сырого JSON (копирование/вставка) и drag-and-drop файлов с выбором стратегии разрешения коллизий (Merge / Replace).
*   **`ProductCard.tsx`**: Сложный реактивный элемент карточки товара. Оптимизирован через `React.memo`, инкапсулирует логику отслеживания локальных изменений (цена, размеры, описание) по сравнению с оригинальным состоянием.
*   **`ProductMediaGallery.tsx`**: Адаптивная галерея изображений товара с индикацией количества фото, кнопкой раскрытия лайтбокса и локальными чекбоксами выбора.
*   **`ProductPriceEditor.tsx`**: Inline-редактор цены со встроенной валидацией ввода.
*   **`ProductTextEditor.tsx`**: Inline-редактор текстовых описаний и оригинальных логов с функцией автосохранения по блюру.
*   **`ProductMetaBar.tsx`**: Мета-информация товара (просмотры, лайки, дата, источник, оригинальные размеры).
*   **`StatsSummaryPanel.tsx`**: Аналитическая панель (всего товаров, сумма активов, средняя цена, количество правок и избранного).
*   **`TagCategoryCloud.tsx`**: Быстрый визуальный фильтр-облако по популярным категориям и кураторским тегам.
*   **`ToastProvider.tsx` / `ConfirmModal.tsx`**: Сервисы системных нотификаций и модальных прерываний действий.
*   **`ErrorBoundary.tsx`**: Предохранитель рендера, перехватывающий ошибки в дочерних компонентах.
*   **`ScrollToTop.tsx`**: Кнопка быстрой прокрутки страницы вверх.
*   **`Lightbox.tsx`**: Компонент полноэкранного просмотра галереи изображений с поддержкой клавиатурной навигации.
*   **`PaginationControls.tsx`**: Постраничная навигация с выбором размера страницы.

## 4. Контракт импорта/экспорта данных (JSON Спецификация)

Интеграция между модулем **PARS** (сбор данных из внешних API) и **KATALOG** осуществляется посредством общих JSON-файлов.

### 4.1. Схема обмена данными
Каждый объект товара при импорте проходит обязательную фазу очистки и приведения типов в `product-normalizer.ts`.

```typescript
export interface Product {
  product_id: string;             // Уникальный идентификатор (обязательно)
  price: number;                  // Текущая цена (обязательно)
  original_price: number;         // Базовая цена до наценки/скидки
  main_image: string;             // Главная обложка товара
  images: string[];               // Полный массив URL изображений
  original_text: string;          // Неизменяемый текст из первоисточника
  description: string;            // Кураторское описание товара
  source_url: string;             // Ссылка на оригинальный пост (VK / Telegram)
  group_products: string;         // Категория товара (Обувь, Куртки и т.д.)
  sizes: string[];                // Модифицированный размерный ряд
  sizes_original: string[];       // Исходный размерный ряд
  date?: string;                  // Дата публикации/импорта
  photos_count?: number;          // Количество изображений
  comments_count?: number;        // Счетчик комментариев
  likes_count?: number;           // Счетчик лайков
  starred?: boolean;              // Флаг избранного
  selected?: boolean;             // Флаг выделения в таблице
  is_modified?: boolean;          // Маркер ручной модификации куратором
  tags?: string[];                // Кураторские теги классификации
}
```

## 5. Выявленные точки хрупкости (Fracture Points) и риски регрессии

В ходе детального аудита кодовой базы V4 были обнаружены следующие критические участки, требующие особого внимания при внесении изменений:

1.  **Сверхнагруженный Context (`CatalogContext.tsx`)**:
    *   *Проблема*: Компонент `CatalogProvider` объединяет в себе управление данными, фильтрацию, сортировку, пагинацию, модальные диалоги, тосты и эффекты URL.
    *   *Риск*: Любые изменения в механике фильтрации могут заблокировать жизненный цикл системных тостов или вызвать бесконечный цикл обновлений URL из-за некорректного срабатывания `useEffect`.
2.  **Недетерминированная генерация ID (`product-normalizer.ts`)**:
    *   *Проблема*: При отсутствии `product_id` normalizer генерирует `crypto.randomUUID()`.
    *   *Риск*: В случае импорта методом `merge` (слияние) товары без ID будут дублироваться при каждом повторном импорте одного и того же файла, засоряя базу данных.
3.  **Асинхронность до закрытия окна (`catalog-db.ts`)**:
    *   *Проблема*: Метод автоматического сброса буфера изменений на событие `beforeunload` использует асинхронный вызов `flushWrites()`.
    *   *Риск*: Браузеры не гарантируют выполнение асинхронных операций (промисов) после закрытия вкладки. Часть накопленных в течение последних 300мс изменений может быть потеряна.
4.  **Каскадные откаты optimistic-обновлений**:
    *   *Проблема*: При ошибке записи в IndexedDB (`updateProduct` / `bulkUpdateProducts`) стейт приложения полностью перезаписывается через тяжелый метод `catalogAPI.getAll()`.
    *   *Риск*: При сетевых или дисковых задержках на слабых устройствах интерфейс может заметно "мигать" или откатываться назад, дезориентируя куратора.

## 1) Краткий синопсис

PARS V2 — локальный SPA-анализатор постов VK, построенный на React + Vite + TS. Покрывает полный цикл: импорт JSON `wall.get` или live-парсинг, NLP-разбор текста, извлечение цен, инлайн-редактирование, фильтрация, экспорт CSV и JSON, а также обратную публикацию в VK через sandbox/real с пулом токенов.

## 4) Детальный анализ ключевых цепочек

### 4.1 Импорт и CSV-реимпорт

**Оффлайн импорт:** `FileUploader` → `store.importJson` → `parseVkJson` → обогащение `favorites`/`exportedList`/`editsMap` → `setPosts`.

**Обратный CSV-импорт (добавлен в V2):**
- В `src/lib/csv-importer.ts`: потоковый разбор CSV, строгая валидация заголовков (`ID Поста`, `Отредактированный текст`, `Итоговая цена (₽)`), нормализация пост-ID/текста/цен.
- В store добавлен `bulkUpdatePostDetails`, который атомарно обновляет `editsMap` и `posts`.
- В UI: отдельный `CsvImportDialog`, вызываемый из `vk-analyzer.tsx`, не смешивается с первичной загрузкой JSON.
- Пустые ячейки игнорируются — существующие правки не затираются.

**Риски:**
- При повторном импорте `favorites`/`exportedList`/`editsMap` применяются к старому массиву. Если пост был удалён/перезагружен, но с тем же `post_id`, старые флаги переносятся в новый импорт. Поведение осознанное, но не задокументировано.
- `price_details` в `VKPost` сейчас заполняются только в `parseVkJson`, а не обновляются после Text Intelligence / CSV-импорта. Это означает расхождение между отображаемой ценой и её происхождением в UI.

### 4.2 Онлайн-парсинг и VK API

Точка входа: `store.fetchOnlineWall` → возможные варианты:
- `VKPluginManager.enqueue` (при наличии плагина) для пула токенов/RPS
- Прямой вызов VK API через каркас интеграции

JSONP реализован через динамический `<script>` и `window[callback]`. Cleanup происходит, но при параллельных запросах возможны гонки за глобальный объект `window`.

Sandbox поддерживает пресеты групп (одежда, обувь, костюмы, куртки). В реальном режиме токен берётся из ввода пользователя, валидируется через `users.get` JSONP и `groups.get`.

**Риски:**
- Токены VK хранятся в localStorage через `safeStorage`, но в открытом виде (base64 если шифрование не применено). Это нарушение принципа безопасного хранения.
- При 401/token expiry нет автоматического fallback'а на другой токен из пула на уровне UI — ротация, если и есть, живёт в плагинном слое, который не попал в текущий снапшот V2.

### 4.3 Экспорт в КАТАЛОГ

`catalog-exporter.ts` маппит `VKPost → CatalogProduct`. Схема `CatalogProduct` сейчас включает:
- Обязательные: `product_id`, `title`, `price`, `main_image`, `images`, `original_text`, `description`, `source_url`, `group_products`, `sizes`, `sizes_original`.
- Опциональные: даты, счётчики, флаги.

`product_id` генерируется как `vk_{owner_id}_{id}`. Цена берётся из `price_edited ?? price_original`. Поле `sizes` заполняется пустым массивом — не извлекается из текста.

### 4.4 Персистентность и `localStorage`

`safeStorage.ts` — обёртка с автоматической сериализацией `Set`/`Map`. Используется в сторе для:
- `posts`, `favorites`, `exportedList`, `editsMap`
- `priceConfig`
- `exportProfiles`
- `exportLogs`

**Риски:**
- Нет версионирования схемы localStorage. Если изменится структура любого из хранимых объектов, старые данные приведут к падению `JSON.parse` в `safeStorage.getItem` и потерям состояния.
- При ошибках записи (`QuotaExceeded`) `safeStorage.setItem` возвращает `false`, но стор не реагирует на это — правки могут теряться без пользовательского уведомления.

### 4.5 Фильтрация и сортировка

`filteredPosts` в сторе — мемоизированный `useMemo`. Применяет 10+ условий: поиск по тексту/автору/ID/хэштегам, диапазон дат, минимум лайков, диапазон цен, избранное, скрытие экспортированных, плюс 6 вариантов сортировки.

**Риск:** любая ошибка в условии фильтрации или сортировке молча скрывает/портит данные. Нет дебаг-режима.
